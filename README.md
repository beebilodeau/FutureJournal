# FutureJournal

Write tomorrow tonight, as if it already happened.

Future journaling flips the usual diary: each evening you describe the next day
in past tense, the way you want it to go ("Today I closed my first client and
celebrated with dinner"). In the morning you read it back. The next night you
note how it actually went, then write the following day.

## What's in v0.1

- **Write tomorrow**: one entry per day, dated for the day it describes, with
  autosave, spark prompts, feeling tags, and a gentle past-tense nudge that
  spots phrases like "I will" or "going to".
- **Read today**: in the morning the home screen leads with the day you wrote.
- **Reflect**: in the evening it asks how today went (It happened / Partly /
  Not yet, plus a note) before you write the next day.
- **Journal**: every entry by month, with streak, days written, and how many
  came true. Edit, reflect on, or delete any entry.
- **Backup**: download or restore a JSON backup (How it works tab).

## Added in v0.2

- **Daily affirmation**: a card at the top of Write. Built-in lines, a line
  pulled from what you wrote ("I was calm on the call" becomes "I am calm."),
  and your own lines (kept on the device and in backups).
- **Came-true check-off**: the reflection splits the day's entry into
  sentences to tick. Ticks suggest the overall answer; the Journal shows how
  often your written days come true.
- **Streak**: a week row on Write ending with tomorrow, current and best
  streak, and a month calendar on Journal.
- **Speak**: a mic button on the entry box (Web Speech API; hidden where the
  browser doesn't support it). Each pause becomes a sentence at the cursor.

Preview deployments accept `?demo=1` to load sample entries when the browser
has none (never on the live site). Anchors: `#affirmation`, `#streak`,
`#came-true` (opens the check-off any time of day), `#write`, and
`/journal/#calendar`.
- **Installable PWA**: manifest, icons and a service worker so it works
  offline from the home screen.

## Added in v0.3: store prep

- **Privacy page** at `/privacy/` (linked from How it works): entries stay on
  the device, nothing collected.
- **Android and iOS apps** (Capacitor 8) wrap the same static site. App id
  `com.syntheticpush.futurejournal`.
- **Phone storage in the apps**: `src/lib/kv.ts` is the storage under every
  store. On the website it is the same browser localStorage as before (same
  keys, same format, so existing journals are untouched). In the apps it is
  Capacitor Preferences, loaded into memory at start.
- **Backup and restore work in both**, with the same file format, so a
  website backup restores into the app and back. In the app, Save backup
  opens the share sheet (Drive, Files, email). `npm test` runs the round trip.
- **Daily reminder** (apps): a local notification at the time you pick; asks
  for notification permission on Android 13+.
- **App lock** (apps): 4 to 8 digit PIN (stored as a salted hash) plus
  optional fingerprint or face unlock; locks again after a minute away.
- The Speak button is website-only (Android's app web view has no speech
  service); the phone keyboard's mic works in the app.

### Building the apps

```
npm run app:sync        # build the site and copy it into android/ and ios/
npm run app:android     # ...and open Android Studio
npm run app:ios         # ...and open Xcode (Mac)
python3 scripts/make-app-icons.py   # regenerate app icons and splash
```

GitHub Actions (`.github/workflows/app-builds.yml`) builds a test APK on every
push to `store-prep` or `main` and attaches it to the run as
`futurejournal-apk` (not a public release). It also checks that the iOS
project compiles for the simulator.

The test APK is signed with `android/app/sideload.keystore`, a throwaway key
kept in the repo so each build installs over the last one. Google Play needs
your own upload key: create it in Android Studio (Build > Generate Signed App
Bundle) and keep it out of the repo.

The journaling day rolls over at 4 AM, so writing at 12:30 AM still counts as
"tonight".

## Stack

Next.js 16 (App Router, static export) · React 19 · Tailwind CSS 4 · TypeScript.
No backend yet: entries live in the browser's `localStorage`.

```
npm install
npm run dev     # http://localhost:3000
npm run build   # static site in out/
```

Icons are generated by `python3 scripts/make-icons.py` (needs Pillow).

## Code map

- `src/lib/store.ts`: the `JournalStore` interface and its implementation
  over `src/lib/kv.ts`. The UI only talks to `store`.
- `src/lib/backup.ts`, `reminder.ts`, `lock.ts`: backup files, the daily
  reminder and the app lock.
- `src/lib/dates.ts`: day keys and the 4 AM rollover.
- `src/lib/tense.ts`: the past-tense nudge.
- `src/lib/stats.ts`: streak and outcome counts.
- `src/components/EntryEditor.tsx`, `ReflectCard.tsx`: the two core
  interactions.
- `src/app/`: Write (`/`), Journal (`/journal`), How it works (`/about`).

## Adding accounts (Supabase), next

Entries are per-browser today, so they don't sync between devices. To add
accounts:

1. Create a Supabase project with a table
   `entries (user_id uuid, date date, text text, feelings text[],
   reflection jsonb, created_at timestamptz, updated_at timestamptz,
   primary key (user_id, date))` and row-level security
   `user_id = auth.uid()`.
2. Add a `supabaseStore` that implements `JournalStore` (make the methods
   async, or keep a local cache and sync in the background).
3. Add magic-link sign-in; on first sign-in, upload the existing
   localStorage entries so nobody loses their history.
4. Remove `output: "export"` from `next.config.ts` if you add server routes
   such as the auth callback.
